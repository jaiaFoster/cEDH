TopDeck.gg API

Complete reference for TopDeck.gg's tournaments API. Access data on tournaments, players, and standings. Seamlessly integrate tournament data into your projects.

Usage Requirements

The TopDeck.gg API is free to use, providing tournament data for your projects and applications.

Rate Limits

Most endpoints allow 100 requests per minute. Heavier endpoints like bulk tournament queries have lower limits. You'll receive a 429 response if you exceed your limit. Need more? E-mail us at [email protected].

Attribution Required

Any project using the API must include a visible credit and link back to TopDeck.gg. See the attribution example on the right.

Info
By using the API, you agree to these requirements. Thank you for supporting TopDeck.gg!

Authentication

All endpoints use the following base URL:

https://topdeck.gg/api

Every request must include your API key in the Authorization header. Keys are free — create one from the developer portal.

Staff View

Building a tool for an event you staff? Add ?view=staff to a single-tournament read — /v2/tournaments/{TID}, /standings, /players/{ID}, /players/{ID}/table, /rounds, /rounds/latest or /rounds/{n} — to see decks as the tournament manager shows them to staff: decklist, deckObj, archetype and archetypeInput while the event runs, and leader before it starts.

Your API key's account must hold a staff role on that tournament (any role — the same check as /attendees); otherwise the request returns 403. Without the parameter, every read follows the public rules. Contact details (email, Discord) stay on /attendees.

Staff-view responses are never cached. Decklists make them larger, so poll /rounds/latest or /players/{ID}/table rather than the full tournament.

Example Request
curl "https://topdeck.gg/api/v2/tournaments/{TID}/rounds/latest?view=staff" \
  -H "Authorization: YOUR_API_KEY"
POST/v2/tournaments

Search completed tournaments. Returns standings, decklists, and optional round data. Filter by TID, or by game + format + date range.

Request Body

Use either TID mode (specific IDs) or query mode (filters). game and format are required in query mode.

FieldTypeDescription
TIDstring | string[]Tournament ID or array of IDs. Disables query-mode filters.
gamestringGame name. Case sensitive.
formatstringGame format. Case sensitive.
startintegerEarliest tournament start date (unix seconds).
endintegerLatest tournament start date (unix seconds).
lastintegerDays back from today. Alternative to start / end.
participantMinintegerMinimum participant count.
participantMaxintegerMaximum participant count.
columnsstring[]Player fields to include on standings. See allowed values below.
roundsboolean | string[]Include round data. true is shorthand for ["round", "tables"]. Default false.
tablesstring[]Table fields to include when rounds is set. See allowed values below.
playersstring[]Player fields within table rows when rounds is set. See allowed values below.
Allowed values
FieldDefaultValid values
columnsdecklist, wins, draws, lossesname, id, decklist, wins, winsSwiss, winsBracket, winRate, winRateSwiss, winRateBracket, byes, draws, losses, lossesSwiss, lossesBracket
tablestable, players, winner, statustable, players, winner, status
playersname, idname, id, decklist

Including decklist in columns or players also returns deckObj when structured deck data is available.

For leader-based games — Riftbound (the Legend) and Magic commander formats (the commander) — standings rows and round players also carry a leader string: the deck's leader card name(s). Two cards (partners, a background) appear in alphabetical order as "A / B", and a double-faced card by its front face, so the same deck always reads the same. It is always included (no column request needed) and absent when there is no deck or the event has not started yet.

For every other game, standings rows and round players carry an archetype string: the deck's archetype label. It is a staff correction, else the player's own name for the deck when it holds up against the decklist, else an automatic label (deck rules for Magic 60-card formats). Alongside it, archetypeInput is the name the player typed for the deck, as typed — it can differ from archetype (a nickname, or a name the decklist contradicts). Both are present once decklists are public (the event has ended, or the organizer enabled "Show Decks"); each is absent without a value.

Selecting winner in tables also returns winner_id. For 1v1 (Pairs) matches it additionally returns the per-match game score as winner_games and loser_games (null for multiplayer pods and score-based formats).

For team events (e.g. Trios), each standing is one team: name is the combined team name, id and decklist belong to the team captain, and a players array lists the roster (id, name, teamTag, plus decklists when the decklist column is requested). Round tables are per-seat sub-matches: tables from the same team pairing share a match key, and each player carries their teamTag when the organizer configured format tags.

Pass exactly as written (case sensitive).

POST/v2/tournaments/create

Create a tournament owned by your API key's account. Include eventPage to also create a public, discoverable event page with registration; omit it for an unlisted, bracket-only tournament.

Note
Requires an active TopDeck subscription. Limited to 10 requests per minute.
Payments
Payment processing (Stripe/PayPal) cannot be enabled through the API. Configure payments from the web dashboard after creating the event.

Request Body

FieldTypeDescription
namestringTournament name, 4–200 characters. Required.
startDatenumberStart time as a Unix timestamp in seconds. Required.
gamestringGame name exactly as it appears on TopDeck, e.g. Magic: The Gathering. Required.
formatstringA valid format for the game, e.g. EDH. Invalid values return a 400 listing the valid options. Required.
selfReportbooleanAllow players to self-report match results. Defaults to false.
eventPageobjectCreates a public event page. See fields below.
autopilotobjectCreates the event with Autopilot on: it runs rounds, the top cut and the finish by itself. Send {} for the defaults. See fields below. Not available for team formats.

eventPage Fields

FieldTypeDescription
locationstringVenue address, geocoded for event discovery. Required.
contactEmailstringOrganizer contact shown on the event page. Required.
playerCapintegerMaximum player count. Optional.
pricenumberEntry fee displayed on the event page. Optional.
currencystringOne of usd, eur, gbp, jpy, cad, aud, mxn, brl, cop. Defaults to usd.
descriptionstringEvent details. Markdown supported.
allowRegistrationbooleanAccept registrations on the event page. Defaults to true.
publishbooleanSet false to create the event page as an unlisted draft — hidden from event discovery and not publicly viewable. Saving the event from the web dashboard publishes it. Defaults to true.

autopilot Fields

FieldTypeDescription
roundsintegerSwiss rounds, 1–20. 0 or omitted sizes them from the players in round 1.
cutintegerTop cut after the Swiss rounds: 4, 8, 12, 16, 32 or 64 (pod formats: 4, 7, 10, 13, 16, 40 or 64). 0 or omitted ends the event after the Swiss rounds.
startDelayintegerMinutes between publishing a round's pairings and starting its clock, 0–30. Defaults to 3.
firstRoundstringWho pairs round 1: manual (staff; the default), swiss, or bracket (single elimination seating every player; 1v1 formats only). With swiss or bracket, round 1 pairs when self check-in ends, after dropping players who didn't check in.
confirmTimeoutintegerMinutes until a self-reported result its opponent hasn't confirmed or disputed is accepted, 0–60. Applies when results need confirmation. 0 waits for the opponent. Defaults to 5.

POST/v2/tournaments/{TID}/register

Register one or more players by email. Emails matching an account are registered immediately; emails without an account receive an invitation and convert on signup. Returns 409 if the request would exceed the event's player cap — pass overrideCap: true to bypass.

Staff Only
Requires admin role or higher.

Request Body

FieldTypeDescription
emailsstring | string[]Email or array of emails. Required.
overrideCapbooleanSkip the capacity check. Defaults to false.

Response Fields

Each input email appears in exactly one bucket, lowercased.

FieldTypeDescription
addedstring[]Newly registered.
pendingstring[]No account found; invitation sent.
alreadyRegisteredstring[]Already registered or invited. No-op.
failedstring[]Could not be processed.
bannedstring[]Banned by this organizer. Skipped.
capacitynumber | nullEvent player cap, or null if unset.
registeredCountnumberTotal registered: confirmed, pending invites, and offered waitlist seats.

GET/v2/me/tournaments

List tournaments owned by your API key. Defaults to tournaments with a future start date; pass filter=all to include in-progress and past events.

Query Parameters

ParameterTypeDefaultDescription
filterstringupcomingSet to all to include in-progress and past tournaments.

The API uses standard HTTP status codes. Errors return a JSON body with a single error field describing what went wrong.
