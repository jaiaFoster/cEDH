### 0.2 — Unfamiliar/ambiguous cards, and a real ingestion pipeline

Built `sim/ingestion/scryfall.py` — a real (not stub) adapter that bulk-pulls
via Scryfall's `/cards/collection` endpoint (2 requests for 100 cards) plus
per-card rulings (100 requests, rate-limited), and writes
`card.schema.json`-conformant records. All 100/100 names resolved on the
first pull (the one apparent miss, King T'Challa, was just returned under
its full transform-card name `King T'Challa // Black Panther, Hope
Enduring` — expected Scryfall behavior for DFCs, not an error).

Headline findings, now from authoritative data rather than search snippets:

- **La abundancia de Yucahú is Sylvan Library** (Spanish/Portuguese Secret
  Lair alt-name printing, Oracle-identical). Ingested under its canonical
  name.
- **Talon Gates of Madara is a plain Modern Horizons 3 Commander land**, not
  Naruto-themed despite the name.
- **Commandeer's exact cost confirmed: `{5}{U}{U}`**, alt cost confirmed
  (exile two blue cards). Resolves `SIM-0003`.
- **Volatile Stormdrake is the only Energy ({E})-using card in the 98**,
  confirmed via full ingestion, not just spot-check. `SIM-0004` stays open —
  this is a rules-engine design requirement now, not a data gap.
- **King T'Challa and Shang-Chi confirmed Commander-legal** via the bulk
  pull's own `legalities.commander: "legal"` field — no longer just a
  search-snippet-level claim.

**Important methodology finding — a WebSearch "verification" turned out to
be wrong.** During the pre-bulk-pull spot-check pass, WebSearch reported
Swift Reconfiguration as mono-blue `{U}` from "Kamigawa: Neon Dynasty
Commander." The real Scryfall data says mono-white `{W}`, with rulings dated
2022-02-18 matching the original Kamigawa: Neon Dynasty printing. Neither
version breaks WUBG legality (W is in-identity either way), but this is a
concrete, in-repo case of exactly what the charter's source hierarchy
predicts: a Tier-6-adjacent source (WebSearch synthesis) contradicted by
Tier-3 authoritative structured data (Scryfall), and the authoritative
source was right. Four more `well_known` cards also had wrong details
surface only once the bulk pull ran: Avacyn's Pilgrim, Delighted Halfling,
Elves of Deep Shadow, and Gaea's Cradle were all under-scoped on color
identity — each has a **mana ability that adds a color not reflected in the
card's casting cost**, which a name-recognition-only check missed but which
color identity rules (CR 903.4) require counting. All logged as `SIM-0006`,
resolved, no legality impact. **Takeaway for the rest of this project:**
treat any "verified_by_search" or "well_known" tag from before 2026-08-12's
network fix as provisional, superseded now by the real card cache.

## Phase 2 — interaction discovery, first pass (real findings)

Ran `sim/ingestion/spellbook.py` against all 100 subject-deck card names via
Commander Spellbook's public `/variants?q=card="..."` search (the
`find-my-combos` endpoint requires auth we don't have). Touched 3,853 unique
variants; classified each by whether every card it uses is already in the
deck. Six are:

1. **Devoted Druid + Swift Reconfiguration → infinite green mana.** Swift
   Reconfiguration turns Devoted Druid into a Vehicle (not a creature unless
   crewed), so the -1/-1 counters from its untap ability never trigger a
   "0 toughness" death — tap for G, add a counter to untap, repeat.
2. **Devoted Druid + Hazel's Brewmaster → infinite green mana (a second,
   independent line).** Hazel's Brewmaster exiles a graveyard creature card
   and makes a Food that gains all its activated abilities; a Food isn't a
   creature, so a Food that "is" Devoted Druid via this effect has the same
   "-1/-1 counters don't kill it" property. Needs Devoted Druid in the
   graveyard first.
3. **Faerie Mastermind + Smothering Tithe + (Clever Impersonator | Kinnan,
   Bonder Prodigy | Training Grounds) → infinite card draw / Treasures**,
   three separate variants. This directly confirms the assignment's named
   seed "Smothering Tithe / Faerie Mastermind loops."
4. **Oboro Breezecaller + Talon Gates of Madara + Gaea's Cradle → infinite
   green mana + infinite landfall triggers + repeatable phase-out.** Loop:
   tap Cradle, tap Talon Gates for {C}, pay {2} to bounce Talon Gates via
   Oboro Breezecaller (untapping Cradle), replay Talon Gates for {4} from
   hand (retriggering its phase-out ETB). Spellbook states "at least five
   creatures" as the prerequisite; **this agent's own mana-accounting pass
   suggests the loop may only break even at exactly five creatures and need
   six+ to be truly infinite** — flagged as `SIM-0007`, needs precise Phase
   3 verification, not taken on faith.

Also logged 112 "one card away" near-misses to
`interactions/one_card_away_from_deck.json` (not written as candidate
interactions — they aren't real lines in this exact 98). Most notable:
Hullbreaker Horror appears as the single missing piece across three
separate high-popularity Sol Ring / Mana Vault / Mox Amber storm-count
loops — a genuine deckbuilding data point for the Phase 33 ablation
framework later, not acted on now.

**All 6 are `status: candidate`, not `verified`.** Per charter non-negotiable
rule 1, none may be used as a deterministic transition in simulation until
Phase 3 (exact-line validation, ideally cross-checked against an executable
engine) confirms them.

## Phase 3 — exact-line validation, first pass (real findings, real caveats)

Two pieces of work, neither yet backed by an executable engine
(`INFRA-0003` build in progress, see below):

**Independent pairwise interaction discovery** (beyond Spellbook's index,
per charter Phase 2 requirement). Grepped all 100 cards' ingested Oracle
text for keyword buckets (mana doublers, untap effects, cost reduction,
free/pitch casting, sac outlets, ETB value, graveyard recursion, tutors,
phasing, copy effects) and manually reasoned through cross-bucket hits.
Two concrete outcomes:
- Kinnan, Bonder Prodigy's actual doubling clause ("add one mana of any
  type that permanent produced") didn't match any of the keyword buckets
  (no literal "twice"/"additional"/"copy") — a reminder that keyword
  search is a starting point, not a substitute for reading the card.
- Delney, Streetwise Lookout doubles the triggered ability of every
  power-≤2 creature it shares a battlefield with. Checked P/T for every
  ETB/triggered-ability creature in the deck and wrote 4 new candidate
  interactions (`INT-0007`..`0010`): Orcish Bowmasters (double removal/
  amass), Esper Sentinel (double tax), Runic Armasaur (double draw off
  opponent activated abilities), Spellseeker (double tutor). Three more
  qualify (Faerie Mastermind, Archivist of Oghma, Badgermole Cub) but
  weren't written up individually — noted here rather than silently
  dropped, since bounding scope needs to be visible, not just implicit.

**Mana-accounting review of the 3 Faerie Mastermind + Smothering Tithe
variants** (`INT-0001`, `INT-0004`, `INT-0005`). Pulled each variant's full
Spellbook description and hand-checked the mana math, the same way as
`INT-0006`. Found the same *shape* of ambiguity — partial-Treasure-cracking
in the described lines makes a confident by-hand correction risky (unlike
`INT-0006`, where the accounting was clean enough to state a specific
threshold). Chose NOT to assert a corrected number here rather than
compound one hand-parse with another — flagged in each record instead, and
deferred to real engine reproduction. **More significant than the exact
math**: all three variants explicitly require multiple opponents who choose
not to pay Smothering Tithe's {2} tax — an opponent decision, not something
this deck controls. That's a materially different reliability class than
the fully self-contained Devoted Druid lines, and needs to be reported
separately once Phase 26 (combo accessibility) and Phase 29 (interaction
burden) exist to quantify it, not blended into one "combo count."

**Forge/XMage adapter spike (`INFRA-0003`), in progress.** Confirmed both
JDK 21 and Maven/Gradle are available in this environment. Found that
XMage's `Mage.Tests` module already contains an existing
`DevotedDruidTest.java` using a JUnit-based DSL
(`addCard(Zone, player, name, qty)`, `activateAbility`,
`checkPermanentTapped`, `waitStackResolved`, `setStopAt`, `execute()`) that
is close to a direct match for this project's own gold-board-state format
— strong evidence for XMage specifically as the Gate 2 execution substrate,
independent of the earlier card-coverage tie. A full clone (`--depth 1`,
294MB) and a scoped Maven build (`Mage`, `Mage.Sets`, `Mage.Tests` modules
only, `-DskipTests`) is running; once it finishes, running the existing
`DevotedDruidTest` end-to-end would be the first real Level-4 reproduction
this project has, and a template for writing new tests against `INT-0002`/
`INT-0003`/`INT-0006`.

## MTGJSON cross-validation — scoped out for now (deliberate, documented)

Per charter, MTGJSON exists to cross-validate Scryfall data, not replace it.
Checked feasibility: MTGJSON has no lightweight per-card REST lookup — only
full bulk-file downloads (`AllPrintings.json` ~655MB, `AllIdentifiers.json`
~633MB), confirmed via `HEAD` request content-length. Downloading either to
cross-check 100 already-authoritative Scryfall records is a poor cost/benefit
trade in a disk-constrained sandboxed environment, especially since the
Scryfall data has already proven internally consistent on every spot-check
run against it (Devoted Druid, Commandeer, Gaea's Cradle abilities all
matched independent expectations; Forge's own card scripts, sourced
separately by the Forge maintainers, matched the Scryfall Oracle text
exactly on 3 spot-checks). This is a scoping decision, not a silently
dropped requirement — logged here so it's auditable, and revisited if a
specific card's data is ever in doubt and a targeted single-set MTGJSON file
(much smaller than the full bulk files) would resolve it.
